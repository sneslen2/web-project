================================================================================
WHAT THE AI WAS USED TO ACHIEVE
================================================================================

Working from my feature outline, the AI built the entire application:

  * Supabase integration -- database client, email/password accounts, session
    handling, and a SQL schema with Row Level Security policies restricting each
    user to their own data.

  * A web scraper that pulled Agatha Christie's complete catalog (302 novels,
    collections, plays, and short stories) from agathachristie.com, including
    each story's synopsis, background prose, trivia, quotations, cover image,
    and related titles.

  * Five pages: a home page with progress summary, a filterable/sortable
    checklist of all 302 stories, an individual page per story with reading
    status/rating/notes, a statistics page with completion breakdowns, and an
    Agatha Christie biography page.

  * The data pipeline -- an import script loading the catalog into Supabase, and
    the client code fetching it at runtime.

  * Testing and documentation -- automated browser tests confirming every route
    renders, plus the README and a developer reference document.

It also recovered a scraper I had lost from an earlier session by searching local
session transcripts, and reconstructed its source.


================================================================================
MY ROLE
================================================================================

I directed the project and made the design decisions; the AI implemented them.

DEFINED THE PROJECT. The concept, subject matter, and feature set were mine: a
Christie reading tracker with a home page, filterable checklist, per-story pages,
a biography page, and user statistics. I specified accounts with saved per-user
data rather than a simpler local-only tracker.

MADE THE ARCHITECTURAL DECISIONS. The AI presented options at each decision
point and I chose:
  - Story URLs use readable slugs (/#/story/the-mysterious-affair-at-styles)
    rather than array indices or database UUIDs.
  - Reading progress tracks status, star rating, and notes, not just read/unread.
  - Nested data (trivia, related stories) stored as columns on the stories table
    rather than in separate child tables.
  - The app fetches the catalog from Supabase at runtime rather than bundling it.
  - The Supabase publishable key is hardcoded rather than read from a .env file,
    after being advised the key is designed to be public and that Row Level
    Security is the actual protection.

FOUND A BUG THE AI MISSED. I noticed the checklist's detective filter was
listing entries like "Collection (11 stories)" and reported that data had been
misfiled. This was a genuine defect in the AI-written scraper: collection pages
label the format "Collection (7 stories)" rather than "Collection", so the
parser's exact-match check failed and the whole string was written into the
detective field. Investigating my report also surfaced three related cases
("Mary Westmacott", "Detection Club", "Inspired by" -- all stored as
detectives). 18 records were wrong. Without my review this would have shipped.

OVERRODE THE AI'S JUDGMENT. When the repair script proposed discarding the
"Inspired by" value as meaningless, I rejected that and directed it be preserved
in a new attribution field, since it marks novels other authors adapted from
Christie's plays.

CONTROLLED THE PROCESS. I rejected several proposed edits until they were
explained, required the AI to summarize each change before applying it, and
approved installing browser-testing tooling so changes were verified in a real
browser rather than assumed correct from a successful compile.

DID THE WORK THE AI COULD NOT. The AI never had access to my Supabase secret
key, so I applied the database schema and ran the data import myself. I also ran
the linter, which would not execute in the AI's sandbox, and handled deployment.


================================================================================
THIRD-PARTY CONTENT
================================================================================

Story metadata (titles, synopses, publication years, trivia, quotations, cover
image URLs) was scraped from agathachristie.com and is owned by Agatha Christie
Limited. It is used here for a non-commercial academic project. The scraper
checks robots.txt, identifies itself as a student project, and waits one second
between requests. Cover images are hotlinked to the site's CDN, not copied.
